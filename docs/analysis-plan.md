# 次の分析で確かめること

SU数が回答精度を説明できる範囲を、コードごとのデータで調べる。今回の結合修正と、新しい主分析の採用は分ける。保存結果を再現できることと、分析方法が研究目的に合うことも別の問題である。

## 分析の単位を先に決める

回答精度は、同じ設問への正解数 `k` を実際の試行数 `n` で割った値である。予定が5回でも、欠損を含むデータの分母を自動で5にしない。欠損と、実行した結果の不正解は区別する。

HumanEvalには162個の基本IDがあり、それぞれ3個の設問IDがある。各設問には5回の回答がある。今回の結合修正は完全IDを使い、基本IDの設問を指標に結び付ける。派生設問を足して15試行とする変更は含めない。派生設問間でコードも異なる例があるため、先にコードの一致を確認する必要がある。

同じコードへの5回の回答を、独立した5個のコードとして数えない。設問を分けて使う場合も、同じコードや同じ課題に属する行をまとめて扱う。学習用と検証用の分割、ブートストラップの再抽出も、この単位を保つ。

## 三つの方法の比較

| 方法 | 分かること | 0〜1の平均値の扱い | 前提と注意点 |
| --- | --- | --- | --- |
| 事前に決めたSU区間内の相関・傾き | その区間の中で、SUが多いコードほど回答精度が変わるかを調べる。 | コードごとの `k/n` を使う。順位相関または最小二乗の傾きを推定し、コード単位の再抽出で不確かさを示す。 | 区間内にSUの異なるコードが必要である。幅1ではSUが一定となり、SUとの相関は定義できない。件数、SUの幅、精度のばらつきを併記する。 |
| 正解数を使う二項ロジスティック回帰 | SUが増えたときの正解確率の変化を、LOCや課題の違いも考慮して推定する。 | `k ~ Binomial(n, p)` として `k` と `n-k` を渡す。0と1もそのまま扱える。 | 条件をそろえた試行の独立性と、基本形ではSUとlogitの直線関係を仮定する。過分散、完全分離、LOCとの強い相関を点検する。 |
| 二項分布を使うスプライン・GAM | 傾きが変わる範囲や、曲がった関係を調べる。 | 同じ `k,n` を使い、`logit(p)=s(SU)+…` と表す。 | 曲線の自由度を抑え、コード単位の検証で過学習を確かめる。少数しかない高SU域では推定が不安定になる。境界を探してから通常のp値だけを報告しない。 |

二項モデルの入力形式は、[statsmodelsのBinomialの説明](https://www.statsmodels.org/stable/generated/statsmodels.genmod.families.family.Binomial.html)に対応する。非線形モデルの候補は、[mgcvのGAMの説明](https://www.stat.ethz.ch/R-manual/R-devel/library/mgcv/html/gam.html)を参照する。

最小二乗は、`k/n` と予測値の差の二乗を小さくする。二項回帰は、試行数を含む二項尤度を使う。両者は同じ計算ではない。現行の `semantic_unit_model_comparison.py` の `logistic` は4パラメータ曲線の最小二乗である。`curve_fit` という関数名からも確認できる。[SciPyの説明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.curve_fit.html)も非線形最小二乗としている。

最小二乗を使う場合は、平均値が離散的であり、分散が正解確率と試行数に依存する点を考慮する。二項回帰を使う場合も、反復回答の独立性を無条件には仮定しない。依存や過分散が残るときは、コードをまとめた標準誤差や、準二項・ベータ二項モデルを検討する。

## 手順を固定する

1. 入力、完全ID、コードの一致、`k,n`、SUの定義と閾値を確定する。p80は保存値に対応する閾値1.3238を使う。古い結合表とは混ぜない。
2. 主分析は、課題別の二項回帰を候補とする。SUとLOCを同時に入れる理由を決め、LOCだけのモデルとも検証データ上の予測を比較する。SUの追加で予測が改善するかを確かめる。
3. 区間は精度を見ずに決める。区間内のSUの異なり数と件数が不足する場合は、推定不能と報告する。区間同士の傾きの違いは交互作用でも確かめる。
4. 非線形モデルは感度分析として比較する。候補、自由度、検証方法、報告する指標を先に固定する。境界探索を使うなら、探索と評価に同じコードを使わない。
5. 候補の全結果と不確かさを残す。有意な区間、閾値、群数だけを選ばない。複数の検定をするなら検定群を定め、補正方法も先に決める。

修正前のp67保存表では、HumanEvalは162コードでSUが4〜22、APRは271コードで16〜593、翻訳は535コードで2〜182である。修正後のHumanEvalでは158件中146件の精度が1.0である。誤答を含むコードは12件しかなく、細かい区間では精度のばらつきがなくなる。二項回帰でも完全分離や大きな推定誤差に注意が必要である。

この分布だけでも、同じ幅の区間が全課題に同じ意味を持つとはいえない。混合した散布図は課題構成の違いを表す場合がある。これは方法選択の根拠であり、新しい主分析の結果ではない。

## 教授に説明する要点

先行研究の群分けは、個々のコードのばらつきを減らし、群の代表値同士の関係を見る方法である。自分の目的は、SUのどの範囲でコードごとの回答精度を説明できるかを確かめることにある。区間平均の上下だけでは、その区間の内部に関係があるとはいえない。

先に結合と算出経路を直し、保存結果の再現範囲を示す。そのうえで、区間内の関係と正解確率のモデルを比較する。新しいSU抽出規則や主分析は、今回の不具合修正とは別に提案する。
